mulation

Prove your tests would catch the bug.

A mutation-testing layer on Google Test and CTest — not another framework. Compile once with Clang, flip mutants at runtime, gate PRs on score.

Download release View source

Same habit as Valgrind

mulation --git-diff --min-score 80 -- ./build/my_tests
mulation --git-diff --min-score 80 -- ctest --test-dir build

Keep writing TEST / EXPECT_*. Instrument product code with mulation c++, leave CTest as the unit runner, use mulation as the pre-production gate.

Install from a release package

tar xf mulation-bot-*-linux-x86_64.tar.gz
# copy bin/, lib/, include/ into /usr/local or $HOME/.local
sudo apt install clang-18 llvm-18   # plugin needs LLVM 18

CXX="mulation c++" CC="mulation cc" cmake -B build && cmake --build build
ctest --test-dir build
mulation --git-diff --min-score 80 -- ./build/my_tests

What the score means

  • killed — suite failed or timed out under the mutant
  • survived — suite stayed green
  • score — killed / (killed + survived)

Honest limits

  • Linux + Clang/LLVM 18 today
  • Needs a rebuild with the pass plugin (not pure DBI)
  • Prefer --git-diff so PR campaigns stay cheap
